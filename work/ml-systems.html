01 / Problem

One full training epoch, on a laptop.

I started with a deliberately naive, single-threaded C++ baseline and optimized a fixed autoencoder on 2,700 PBMC3k single-cell gene-expression profiles.

01

Keep the training target fixed

MSE loss, Adam at learning rate 1e-3, and batch size 256. I optimized the implementation while preserving the required accuracy.

02

Find the expensive work

The input was approximately 94% zero, but reconstruction was dense and 13,714 elements wide. Those layers needed different approaches.

CIS 677 High-Performance Computing · Instructor: Zachary DeBruine · HPCBench handle: ghnimim

02 / Optimization path

Change the data path, then the kernels.

I worked through these changes in order, measuring each stage and keeping an experiment log, including unsuccessful attempts.

  1. 01

    Sparse input

    I skipped zeros in layer-1 forward and gradient computation.

  2. 02

    OpenMP

    I used four threads. Each thread owned independent rows to avoid write conflicts.

  3. 03

    Memory layout

    I moved Adam state to struct-of-arrays storage so the compiler could vectorize its loops.

  4. 04

    Cache blocking

    I split the wide reconstruction layer into column panels sized for L1-cache locality.

  5. 05

    AVX2/FMA

    I wrote register-blocked intrinsic kernels that combined forward, loss, and backward work within each panel.

  6. 06

    Mixed precision

    I used float32 for the heaviest layer, with float64 for Adam and the remaining computation. Required accuracy was preserved.

  7. 07

    Systems overhead

    I compressed sparse input from 296 MB to 27 MB, reused buffers, used huge pages, fused Adam updates into gradient kernels, and parallelized remaining serial work.

Measured progression

9.94× → 10.33× → 23.20× → 24.73× → 57.67×

The final overhead stage reduced runtime from 1.54 s to 0.97 s. Full credit required a 10× speedup.

Tools: C++17 · OpenMP · AVX2/FMA intrinsics · SIMD · GCC · Linux / WSL2 · Python · Performance profiling · Cache and memory-layout optimization

04 / Measurement & what I learned

Compare runs in the same session.

Thermal behavior moved the raw baseline between approximately 50 and 65 seconds. I compared same-session benchmark ratios rather than treating isolated raw timings as directly comparable.

Engineering lesson

I kept correctness as a constraint and logged failed experiments alongside improvements. Memory movement and systems overhead mattered as much as faster arithmetic.

05 / Earlier sparse-kernel foundation

Make memory movement part of the algorithm.

My earlier sparse linear-algebra project built the foundation: packed CSR storage, aligned memory, cache-aware tiling, OpenMP, and SIMD. I applied the same attention to data movement to the later full training epoch.

Storage

Pack the nonzero work

I used CSR and 64-byte alignment to avoid dense traversal over zeros and organize the memory path.

Locality

Tile the dense dimension

I used K-column tiles and specialization to keep active data closer to cache instead of repeatedly traversing the full output width.

Execution

Parallel rows. Vectorized tiles.

I distributed row work with OpenMP static scheduling, applied SIMD within tiles, and used prefetching to support the memory path.
