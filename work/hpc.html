Sparse ML Kernel Optimization

1stPlace
68.78×Geometric-mean speedup
6/6Correctness

Overview

I optimized the sparse linear-algebra kernel used in a transcriptomics ML workload on a 296 MB dataset. The result was first on the leaderboard, with a 68.78× geometric-mean speedup and correct output on all six evaluated matrix widths.

Problem

The sparse input and wide output dimension make memory movement the dominant cost. A naive dense traversal wastes work on zeros and repeatedly stresses memory bandwidth. The baseline was the reference to beat without changing the numerical result.

What I built

  • Packed CSR representation
  • 64-byte alignment
  • OpenMP static scheduling
  • SIMD vectorization
  • Cache-aware K-column tiling
  • Software prefetching
  • Compile-time specialization

Architecture

01 Sparse matrix in packed CSR
02 Cache-aware K-column tiles
03 OpenMP across rows
04 SIMD inside the tile
05 Prefetch the next row
Baseline1×
Optimized68.78×

Engineering decisions

CSR keeps only the nonzero values. Tiling and alignment are there so the dense dimension stays in cache. OpenMP splits rows. SIMD and prefetching only help after the layout is fixed, so they came after the packed format.

Results

#1 on the leaderboard. 68.78× geometric-mean speedup. Correct on 6 of 6 evaluated matrix widths. I am not listing per-matrix timings because those breakdowns are not included here.

What I learned

The large speedup came from the data layout and the memory path, not from a clever arithmetic trick.
