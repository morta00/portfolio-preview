High-Performance Autoencoder Training

A full autoencoder training epoch, same loss as the reference, 24.73× faster than the course baseline.

24.73×Posted speedup
10×Full credit
2.28 sVersus 56.49 s

Problem

The challenge was to accelerate one full training epoch of an autoencoder on a single-cell matrix: 2,700 cells by 13,714 genes, only 6.17% nonzero. The network is 13,714 → 256 → 32 → 256 → 13,714, trained with Adam in batches of 256. The grade is the speedup of that epoch against the course baseline on the same machine. The trained model still has to match the reference loss.

What I built

I kept the model, optimizer, and numerical target fixed, then optimized the training system one bottleneck at a time. The posted entry runs the epoch in 2.28 seconds on an Intel i5-11300H with 4 threads. Five timed runs landed between 2.22 and 2.40 seconds. The baseline on that machine took 56.49 seconds.

Architecture

01 Sparse input, 13,714 genes
02 256 → 32 → 256
03 Dense reconstruction, 13,714
04 Adam, batch size 256

Engineering decisions

Each number below is a posted score after that change, not a guess.

  • Skipping zeros in the first layer: 1.54×. The last layer is dense, so sparsity alone does not carry the epoch.
  • Four threads: 3.55×.
  • Separating the weights from the Adam moments: 6.73×.
  • Blocking the last layer and using 256-bit vectors: 10.33×, which clears the full-credit line.
  • Splitting the 13,714 outputs into width-16 AVX panels, and running the forward pass and both gradients on each panel together: 23.20×.
  • Keeping 16 gradient outputs in registers: 24.73×.

A horizontal dot product on the same gradient still matched the loss and scored 20.78×, so I left it off the final posted version.

Results

24.73× versus the course baseline, with the same loss as the reference. Full credit was 10×. This is a course measurement on one laptop, not a public benchmark.

Stack

C++AVXAdamMultithreading

What I learned

Optimizing a neural network training step is a systems problem, not just a model problem. The first layer is sparse, but the reconstruction layer is dense; the largest gains came from memory layout, blocking, vectorization, and keeping gradient work close to the data rather than from skipping zeros alone.
