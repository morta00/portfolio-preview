GeoAgent

Agentic AI research and data-analysis platform

Overview

GeoAgent is an autonomous AI platform I am building for multi-step research and data-analysis workflows. The goal is a system that can plan, choose tools, execute, verify, and write a grounded report, with retrieval, Python analytics, and SQL available inside the workflow.

Problem

Useful analysis rarely fits in one model call. A researcher has to retrieve context, query data, run code, check the result, and only then write the answer. GeoAgent is the attempt to put that loop into an explicit agent workflow instead of a single chat prompt.

What I am building

There is no public repository for GeoAgent yet, so I am not listing these pieces as finished. They are the parts currently being built:

  • Planner, executor, and verifier roles
  • Tool calling and a tool router
  • RAG over stored context
  • Persistent workflow state
  • Failure recovery and replanning
  • Human approval for sensitive actions
  • Grounded reporting
  • Python analytics and SQL analysis
  • An evaluation framework

Engineering decisions

The stack is chosen so planning, retrieval, and data access stay separate: LangGraph for the workflow, MCP for tools, FastAPI for the service boundary, PostgreSQL and pgvector for state and retrieval, and Docker for running the pieces together.

Design and implementation are underway. I will replace this section with measured results only after the evaluation framework has numbers worth reporting. No accuracy, latency, or user metrics are claimed yet.

What this is forcing me to learn

How to keep an agent inspectable: separate planning from execution, make tool use visible, and require a check before a result is treated as an answer.
